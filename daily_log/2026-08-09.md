# Agent 学习日志 Demo10 + Demo11
## Demo10 滑动窗口记忆优化
### 学习内容
1. 实现对话滑动窗口机制，推理时仅截取最近N轮对话传入模型，控制上下文token数量，解决长对话推理速度持续变慢问题；本地JSON文件完整存储全部对话记录，不会丢失历史消息。
2. 复用已调试稳定的 tool_router 时间工具调度、rag_utils 检索模块，各模块职责解耦，无代码耦合。
3. 优化提示词硬性约束，增加限制规则，解决模型回答时附带上一轮无关内容、重复输出旧答案的问题。

### 实操踩坑与解决方案
1. 模型回答附带上一轮对话无关内容
    - 问题原因：原始提示词未限定回答范围，小模型会整合全部上下文信息输出；
    - 解决方法：补充强制规则，要求模型仅针对用户当前最新提问作答，禁止复述历史对话内容。
2. 区分两个核心概念：滑动窗口仅用于模型推理输入截断，本地文件持久化存储完整对话，二者互不冲突。

### 学习收获
分清「模型推理上下文」与「本地持久化记忆」的区别；学会通过提示词约束规范模型输出，减少无关上下文干扰。

## Demo11 工程化RAG向量库全套优化
### 学习内容
1. 向量持久化优化：使用`get_or_create_collection`读取本地已有向量库，无需每次启动程序重新建库、重复文本向量化，大幅缩短启动耗时。
2. 文本分片逻辑收拢至rag_utils公共模块，封装`split_text`函数，支持自定义chunk_size、overlap重叠参数，不再需要外部临时脚本复制分片代码。
3. 检索函数升级：`search_knowledge`增加带默认值的top_n入参，调用时可灵活调整返回知识库片段数量；新增空检索兜底文本，避免无匹配内容时报错。
4. 新增标准化`add_knowledge`批量入库接口，一站式完成文本分片、唯一ID生成、向量写入，RAG实现完整闭环。
5. 理清存储分层：原始txt为可读私有知识库素材，vector_db是Chroma二进制向量库，无法直接肉眼读取，只能通过代码接口查看存储片段。

### 实操踩坑与解决方案
1. TypeError: search_knowledge 无法识别 top_n 参数
    - 原因：旧版函数未定义top_n入参，参数写死在函数内部；
    - 解决：给search_knowledge增加top_n默认参数，支持外部动态传参。
2. 对话历史内容与知识库信息冲突，模型采信错误历史对话
    - 方案1：删除chat_history.json清空错误对话上下文；
    - 方案2：强化提示词规则，规定知识库内容优先级最高，出现冲突直接忽略对话历史。
3. 新旧版本向量库结构不兼容
    - 解决：直接删除项目内vector_db文件夹，新版代码自动生成全新向量库，重新导入私有文本知识。

### 学习收获
掌握工程化RAG优化思路：本地向量复用、分片/入库/检索逻辑统一封装、参数可配置、异常兜底处理；理清原始文本素材与向量数据库存储逻辑；通过提示词优先级规则解决上下文信息冲突问题。
