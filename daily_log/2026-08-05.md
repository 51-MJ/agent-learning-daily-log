# Agent开发学习日志
## 一、demo03 长期记忆代码学习与问题排查
**内容概括**：本次先学习demo03实现对话持久化存储，区分短期与长期记忆的实现方式，运行测试时发现smolagents框架记忆机制存在局限，调试过程还遇到了代码参数、消息格式相关报错，同时梳理清楚报错背后的原因。
**重点阐述**：
1. 记忆实现方式区分：短期记忆依靠`while True`构建交互式聊天循环，对话只存放在程序运行时的内存变量中，一旦关闭终端程序，内存里的聊天数据就会直接清空；长期记忆需要使用`.json`文件，通过`json.load`从硬盘读取历史对话、`json.dump`把对话写入硬盘完成持久化，程序下次启动就能加载之前的聊天内容。
2. 工具代码学习：掌握使用`@tool`装饰器自定义时间查询工具，搭配`CodeAgent`完成工具调用。
3. 问题原因：smolagents自带独立封闭的内部上下文缓存，不会主动读取我自己创建的`chat_history.json`文件；`agent.run()`仅接收当前单条提问，不会自动带入外部保存的历史对话。程序重启后框架内部记忆清空，模型获取不到真实聊天记录，就会产生幻觉，编造不存在的聊天内容。
4. 其他报错与原因：直接在分支调用框架底层模型触发消息嵌套格式报错；尝试添加关闭日志参数时，因本地smolagents版本不支持该参数导致报错，也意识到第三方库使用前要核对版本支持的写法。

## 二、demo04 路由分流 + Ollama原生可控长期记忆开发学习
**内容概括**：针对demo03暴露的记忆不可控问题，编写demo04做架构拆分，将普通聊天、记忆管理和工具调用分开处理，逐行拆解原生接口调用代码逻辑，最后通过运行测试验证该方案可以解决历史对话回忆出错的问题。
**重点阐述**：
1. 解决思路：不完全弃用smolagents，做功能分工；普通闲聊、记忆管理改用Ollama原生接口，只有查询时间这类需要调用工具的提问，才交给smolagents的`CodeAgent`处理，以此绕过框架封闭记忆的缺陷。
2. 关键词路由逻辑：编写`route_judge`函数，通过匹配“几点、时间、日期、星期”等关键词，判断用户问题是否需要调用工具，根据判断结果分流执行不同代码。
3. `chat_normal`函数代码拆解：
   - `messages = chat_history + 当前用户提问`：拼接全部历史聊天和最新提问，这是模型能够回忆过往对话的核心；
   - `payload`是请求数据包，配置了调用模型名称、完整对话列表、关闭流式输出；
   - `requests.post`向本地Ollama服务发送POST请求，`localhost`仅本机内部程序通信，聊天数据不会上传外网；
   - `resp.json()`解析接口返回数据，从返回字典中提取模型回答文本；
   - 保存区分两处：普通聊天在`chat_normal`内部自动调用`save_history`保存问答，工具调用分支则在主循环手动调用`save_history`写入json。
4. 验证结果：重启程序后询问过往聊天内容，模型可读取本地json如实作答，不再编造虚假对话。
