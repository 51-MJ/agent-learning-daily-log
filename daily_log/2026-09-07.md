## Demo12：RAG应答边界约束

### 学习内容
1. **RAG回答边界约束**：检索内容原样使用，不判断其对错；模型回答时只能基于检索内容做合理逻辑推理，禁止编造知识库中不存在的具体事实。
2. **合理推理 vs 凭空编造**：
   - 合理推理：知识库说"初中生"→ 推理出"职业是学生"（逻辑必然，允许）
   - 凭空编造：知识库没写年龄 → 模型说"今年14岁"（无依据，禁止）
3. **模型自我校验能力**：7B小模型没有内置自我校验机制，生成即输出，不会在输出前检查答案是否正确；靠prompt引导的"自我反思"对小模型效果有限。
4. **大模型 vs 小模型**：更强的模型（GPT-4、72B等）遵守规则能力更好，幻觉更少，但不能根除；真正可靠的验证要靠外部代码机制。

### 实操踩坑与解决
1. **CodeAgent的verbosity参数不兼容**
   - 问题：`TypeError: MultiStepAgent.__init__() got an unexpected keyword argument 'verbosity'`
   - 原因：当前安装的smolagents版本不支持verbosity参数
   - 解决：去掉verbosity参数，或用logging模块设置日志级别
2. **模型把"不关注理财投资"标注为【逻辑推理】而非【知识库原文】**
   - 原因：7B模型语义理解能力有限，认为"不关注理财投资相关内容"到"不关注理财"需要推理
   - 解决：在prompt规则中加入正反例，明确什么情况标原文、什么情况标推理
3. **开放式问题触发幻觉**
   - 现象：问"你知道哪些人物"，模型把对话历史里用户提到的"马杰"也编进了知识库人物列表
   - 原因：开放式总结问题比具体问题更容易触发幻觉，模型混淆了对话历史和知识库内容
   - 解决：prompt增加针对列举/总结类问题的约束规则

### 学习收获
- 理解RAG系统中"合理推理"和"凭空编造"的边界
- 认识到7B小模型的局限性：无自我校验、语义理解有限、开放式问题易幻觉
- 掌握通过prompt正反例引导模型标注来源的方法
- 意识到纯靠prompt堆规则不是长久之计，产品级需要代码层控制

## Demo13：多文档知识库管理 + 来源标注 + 增量更新

### 学习内容
1. **多文档知识库管理**：docs/下每个txt是一个独立知识源，存入向量库时带上source元数据标识来源文件，检索时能看到答案出处。
2. **元数据（metadata）**：ChromaDB支持给每个向量片段附加键值对信息（文件名、分类标签），检索时一并返回，可用于过滤、溯源。
3. **回答来源标注**：prompt约束模型回答时明确区分【知识库原文】（直接引用）和【逻辑推理】（基于知识库推导），提升可追溯性。
4. **增量更新**：不用删整个向量库，按source文件名删除旧片段再追加新片段，实现单个知识库文件的热更新。
5. **build脚本双模式**：
   - 全量重建：删除所有旧数据，重新导入全部txt（大改版或结构变更时用）
   - 增量更新：只处理有变动的文件，新增文件追加，已存在文件先删旧再导新（日常维护用）

### 核心代码改造
1. **rag_utils.py改造**：
   - add_knowledge增加source参数，ID包含source避免冲突，元数据记录来源文件名
   - 新增delete_knowledge_by_source()：按来源删除所有片段
   - 新增list_knowledge_sources()：查看向量库已有来源文件
   - search_knowledge增加source_filter可选参数，返回结果带[来源：xxx]标注
2. **build_knowledge_base.py改造**：
   - 支持全量重建和增量更新两种模式
   - 增量模式自动判断文件是新增还是更新，分别处理
3. **demo13_multi_doc_rag.py新建**：
   - 启动时显示已加载的知识库来源列表
   - prompt增加来源标注规则（【知识库原文】【逻辑推理】【无依据】）
   - 复用滑动窗口、时间工具、RAG检索全套能力

### 实操踩坑与解决
1. **来源标注不准确**
   - 现象：知识库原文"不关注理财投资"被模型标注为【逻辑推理】
   - 解决：prompt规则中加入具体正例，7B模型看例子比看抽象规则更容易理解
2. **开放式问题幻觉**
   - 现象：问"你知道哪些人物"，模型编造了知识库中不存在的人物
   - 解决：针对列举/总结类问题增加专门约束，禁止把对话历史中的内容当作知识库内容
3. **前后矛盾**
   - 现象：模型先说知识库有马杰，被质疑后又承认没有
   - 原因：模型能被指出错误后改正，但不能自己主动发现错误
   - 解决：产品级需要代码层回答校验，不能只靠模型自觉

### 学习收获
- 掌握ChromaDB元数据的使用方法，实现多文档溯源和按来源过滤
- 理解增量更新的实现原理：按source删旧再导新，不用全量重建
- 学会设计build脚本的双模式（全量/增量），兼顾大改版和日常维护
- 认识到prompt堆规则的局限性，为后续引入代码层控制、意图分类架构做铺垫

## 三、工程化思考

### 发现的问题
1. 纯靠prompt堆规则解决幻觉，规则越来越多，模型反而记不住
2. 一个大prompt包打天下，不同类型问题（时间查询、知识库问答、闲聊）用同一套约束，互相干扰
3. 7B模型无自我校验能力，生成错误后不能自己发现

### 后续方向
1. **意图分类架构**：不同问题走不同流程，每个流程用精简的prompt
2. **代码层控制**：检索为空时代码直接拦截，不送给模型；回答后代码校验关键实体
3. **结构化输出**：让模型输出JSON，代码解析校验
4. **评测集**：建立固定测试用例，每次改动自动回归测试
