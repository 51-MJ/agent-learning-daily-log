# Demo20 模型自主意图判断

## 学习内容
1. **从关键词路由到模型判断**：之前是代码写死关键词（包含"几点"就走time），现在让模型读题判断意图（time/calculate/search/knowledge/chat），模型理解语义，不管用户怎么说都能识别。
2. **为什么换关键词**：关键词匹配太死板，用户换个说法就认不出来（比如"今世何年月"不含"几点"就识别不出是问时间），而且容易误判（"算一下今年运势"被当成数学计算）。
3. **工作流程**：用户提问 → 模型判断意图 → 根据意图执行对应工具（时间/计算/搜索/知识库/闲聊） → 工具结果+知识库内容 → 流式生成回答。
4. **复用之前代码**：意图判断换了，但工具执行还是走之前的run_tools，RAG、记忆、流式输出全部复用，不重写。

## 关键实现
- `llm_classify_intent()`：用模型判断意图，prompt里列清楚意图选项，模型只返回意图名称
- 意图清洗：模型返回可能带标点或多余文字，做一层清洗，匹配到关键词就返回对应意图
- 其他流程完全复用Demo17-19的代码

## 踩坑与解决
- **7B小模型意图判断不准**："今世何年月"理解成问时间但不调时间工具，直接瞎编年份；"算一下今年运势"被误判为数学计算。这是小模型能力局限，不是代码问题。
- **单意图局限**：一次提问包含多个意图时，模型只会选一个，另一个忽略。多意图是大模型产品的进阶功能，7B小模型做不了。
- **函数名统一**：严格复用已有的run_tools、get_now_time、calculate、web_search等函数，不引入新函数名。
