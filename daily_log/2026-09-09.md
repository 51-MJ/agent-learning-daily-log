# Agent 学习日志 Demo15 + Demo16

## Demo15：流式输出

### 学习内容
1. **流式输出原理**：大模型逐token生成回答，普通模式需等全部生成完成才一次性显示；流式模式生成一个字即打印一个字，用户可即时看到内容输出，显著提升感知速度与使用体验。
2. **Ollama流式API**：调用`/api/chat`接口时设置`stream: true`，接口返回持续推送的数据流，每行一个JSON，包含新生成的内容片段。
3. **requests流式响应处理**：`requests.post(..., stream=True)`不一次性加载响应，配合`iter_lines()`逐行读取，逐行解析JSON并输出。
4. **脱离smolagents框架**：CodeAgent的`run()`方法不支持token级流式输出，因此直接调用Ollama底层API实现流式，同时保留意图分类、RAG检索、工具调度、滑动窗口等全部业务逻辑。

### 关键实现
- `stream_chat()`函数：封装流式调用，`print(content, end="", flush=True)`实现逐字显示，`flush=True`强制立即输出不缓冲。
- 系统提示词与用户内容分离：`system_prompt`存放规则约束，`user_content`存放问题、检索结果、历史等具体内容。

### 踩坑与解决
- **感知速度与实际速度的区别**：流式输出总耗时与普通模式相近，但首字出现时间大幅提前，主观感受更快。
- **框架局限性**：smolagents的CodeAgent存在代码解析与执行的中间层，既影响速度也不支持流式，因此在需要流式输出的场景下直接调用底层API更优。

## Demo16：对话总结

### 学习内容
1. **对话总结的作用**：长对话中，将滑动窗口之外的早期对话自动生成摘要，用摘要替代原始对话送入上下文。既控制上下文长度，又保留早期关键信息，解决"早期对话模型完全看不到"的问题。
2. **摘要与滑动窗口结合**：最终上下文 = `早期对话摘要` + `最近N轮原始对话`。摘要保留早期关键信息，最近N轮保留细节，二者互补。
3. **触发机制**：对话总数超过阈值（默认12条）时触发一次总结，将滑动窗口之外的早期对话生成摘要，并非每轮都总结以节省资源。
4. **摘要持久化**：摘要存入独立的`summary.json`文件，程序重启后仍可读取，避免摘要丢失。
5. **增量总结**：若已有旧摘要，将旧摘要与新的早期对话合并后再次总结，实现摘要的滚动更新，而非每次从头生成。

### 关键实现
- `check_and_do_summary()`：每轮对话后检查对话总数，超过阈值则触发总结。
- `generate_summary()`：非流式调用模型生成摘要，直接返回摘要文本。
- `build_summary_prompt()`：组装摘要生成提示词，要求保留关键信息（人物、事件、重要结论、用户核心诉求），控制在200字以内。
- 上下文组装时，有摘要则在prompt开头加入`【早期对话摘要】`区块，无摘要则省略。

### 踩坑与解决
- **总结频率控制**：每轮都总结会显著增加延迟和资源消耗，设置阈值触发是合理的折中方案。
- **摘要质量**：7B模型生成的摘要可能遗漏细节，因此保留最近N轮原始对话作为补充，摘要仅负责早期信息的概览。

## 工程化思考
1. **从框架到底层的演进**：早期使用smolagents快速入门，理解Agent核心概念；逐步自行实现记忆、路由、RAG等模块；最终脱离框架直接调用底层API，实现流式输出等框架不支持的特性。这是"从黑盒到白盒"的合理学习路径。
2. **记忆管理的演进**：从完整历史 → 滑动窗口（简单截断）→ 对话总结（摘要+近期）→ 后续的相关历史召回（相似度匹配），逐步解决长对话中的信息丢失与上下文长度问题。
3. **感知优化的重要性**：流式输出虽不改变实际生成速度，但显著提升用户体验，是产品化过程中不可忽视的细节。
